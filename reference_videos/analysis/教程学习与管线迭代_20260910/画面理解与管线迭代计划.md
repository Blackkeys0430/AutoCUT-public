**从观众实际怎样理解画面出发**

| 观众需要完成的事 | 教程里有效的处理 | 对我们项目的含义 |
| --- | --- | --- |
| 找到此刻该看的对象，并辨认细节 | 局部近景、明暗分离、准确箭头或曲线；先呈现对象，再解释 | “人物全屏”只解决基础尺寸。讲蕾丝边缘、夹扣、内网时，还要判断这些部位本身是否看得清 |
| 把两个或多个对象联系起来 | 前项保留、末帧定格、当前项突出、同框比较；文字贴近它指向的对象 | 并列句有时间顺序与参照关系。介绍过的对象是否继续保留，由比较需要决定 |
| 看懂动作、变化及结果 | 动作前准备、动作中连续、动作后停留；景别跟着观察任务变化 | 松夹子、放发、翻内网不能只保住句子。应同时保住手、物体和动作结果 |
| 在变化中维持方向感 | 字幕跨镜头保留、前后对象位置衔接、统一边框或画面标记 | 切镜头时可以保留一个识别线索；各层不必在同一瞬间全部消失再出现 |
| 感受到情绪与表达者的态度 | 暗角、局部放大、表情变形、反应画面、快慢反差、短暂空镜 | 画面可以承担情绪、节奏与氛围。使用前判断当前语气、人物形象和内容是否适合 |
| 觉得整片属于同一种视觉风格 | 字体角色、配色、边线、纹理和运动习惯稳定，布局随内容改变 | 统一风格可以容纳全屏、局部、对比、辅助画面等多种构图；要在5.2先选定适合本片的共同特征 |
| 相信画面表达的事实 | 使用真实动作、实物细节和可核对的比较素材 | 保留原始产品的颜色、形状及实际演示。示意图帮助解释，不能补造实物从未展示的结构或效果 |

由此，画面设计可在原步骤中形成一条清楚的因果链：**观察目标 → 选哪段真实画面 → 构图与主次 → 进入、观看和退出的时序 → 文字与声音配合 → 实际装配回读。** 这些内容已经有现成字段承接，不需要再填一份平行计划。

**三位作者分别提供了什么**

Z嗯的价值主要在画面空间和注意力变化：同一段口播可以通过框内取景、背景明暗、人物前后层级、文字位置和运动形成不同观看状态。剪Bingo子的价值主要在组合与时序：并列项如何依次出现、上一项如何保留、背景与人物如何分离、文字如何与画面一起完成表达。十一的整片拉片补充了这些手段在内容中的位置：为什么此处放大、为什么此处停留、为什么切画面时保留字幕，以及多种表现如何保持共同风格。

学习方法、素材渠道、拍摄脚本和工具教学也已阅读。它们对输入准备和工作效率有帮助，但本轮开发重点由画面收益决定；教程中的推广文案、固定参数和效果数量不直接变成生产规则。

**按当前管线推进的实施计划**

1. **把学习结果接回原第五步，先提升画面判断。**

   5.1查看人物动作范围及补充素材实际内容，5.2识别段落作用并选择表现，5.3只绑定台词与使用时间，5.4—5.5落实构图与文字，额外运动参数在5.8补齐；不恢复独立全片节奏、观看任务拆分或5.6规划。概览用于定位，需要跟随、抠像、形变、遮挡或精确落点时，只对有关源区间加密观察，并核对开始、转折、遮挡及结束；轨迹不能从ASR或稀疏概览猜出。前3秒Hook及每2—3.5秒有效视觉推进继续执行，动作和阅读所需的长停留继续说明用途。

   在原手册中加入上述代表案例的使用条件、过程、落定画面、退出方式和容易误用之处；`handbook_refs`直接引用这些案例。补充现有`tutorial_rule_registry_v1.json`的来源关联，保留其候选知识性质。现有预设选择上下文已经能传整片意图和前后段，应继续使用。

   影响文件：剪辑手册、教程规则注册表，必要的PIPELINE摘要与既有NORMAL Memo定位。涉及使用库指导时修改`build_preset_usage_registry.py`后再生成对应使用库与说明，不手改生成物制造分叉。确认后的稳定方法再同步Memo，本研究结论本身不充当用户视觉偏好。

   验收：从当前原素材得到完整可执行的画面安排；关键部位、动作、对比和情绪目的能对应真实内容及操作。共同字体和配色延续，构图变化有观看用途；不以多填字段或效果数量作为完成标准。

2. **用现有操作落实高收益的组合，补少量通用辅助。**

   优先覆盖五种做法：局部靠近并回到整体；真实关键帧保持并准确标注；并列项保留与当前项突出；整体画面与实物细节共同展示；跨镜头保留文字或统一视觉标记。它们作为原计划的操作示例及共享调用组合，不新建剪辑入口或第二种计划格式。

   现有`material-frame/use`、`add_broll`、三类transform及轨道排序可承担较多工作。真实定格已可作为图片进入当前管线，应复用这条路径。若反复需要提取指定源帧、生成准确的线条/箭头、自动拼接末帧保持与静音窗口，则在共享素材模块增加通用辅助，把实际文件、源时间和当前用途接回已有素材绑定。文字、线条与视频仍交同一个CandidateAssembler。

   影响文件：按实际缺口修改`material_library.py`及其已有入口、`shared_operations.py`、CandidatePlan与素材文档；变换能力尽量复用`aroll_motion.py`、`broll_motion.py`、`preset_motion.py`。相关验证使用`test_material_library.py`、`test_shared_operations.py`及受影响的motion、布局、字幕测试。

   验收：真实源区间对应正确；定格不替换必须连续的动作；只有当前需要的原声参与混音；标注指向真实部位；所有叠加层按预定时间进入、保持和退出；前后切点与冻结语音顺序不被辅助画面意外改动。

3. **画面特效模块完善与新增共享能力——正式开发项。**

   目标是把教程中的局部聚焦、前后分层、氛围处理和组合变化变成可调用的共享能力。[特效教程对应清单](<E:/AutoCUT/reference_videos/analysis/教程学习与管线迭代_20260910/特效教程对应清单.md>)中的28项画面效果及组合手法，全部纳入本轮管线迭代的正式改动范围，对应24条教程。以下三类用于组织实现；清单决定具体覆盖范围，表中的首批效果决定推进顺序。原计划漏列的10项同样需要落实，包括人物变形、情绪叠加、透视形变、轮播与显彩、循环字幕、镂空文字、回溯、抽帧和卡点组合。

   对28项逐项落实处理方式：已有可靠能力的，复用并补齐组合调用与相关验证；缺少资源的，完成实际资源接入和绑定；缺少共享能力的，在现有模块中补齐实现。每项在该清单中对应教程依据、现有能力、所需改动、实现状态及验证结果，完成后须能进入同一CandidatePlan/CandidateAssembler供新视频调用。多项效果可以共用底层能力，具体视频按表达需要选择使用。

   **3.1 完善原生视频特效的实际接入。**

   当前`video_effects.py / add_video_effect`已经支持全局或指定片段、命名参数、资源核对及实际绑定回读。这些基础继续复用。本项要把需要的具体效果落实为真实可用资源和调用方案，并补足所发现的参数或作用范围适配缺口。

   | 首批效果 | 具体画面用途 | 要补齐的实际工作 | 验收要求 |
   | --- | --- | --- | --- |
   | 背景模糊 | 背景退后，人物或实物保持清晰；参考剪Bingo子工程拆解5.8秒 | 核对并复用8.8模糊资源及参数；将效果绑定到独立背景层，与前景分层衔接 | 背景发生模糊，前景边缘和需要观察的细节保持清晰；起止时间正确 |
   | 暗角、边缘压暗 | 聚焦、悬念或低落情绪；参考Z嗯开场及十一口播全流程 | 核对对应资源和可调参数，明确影响范围、强度及恢复时间；局部亮区与3.2组合 | 中心主体仍可读；效果随设计出现与结束，不意外延续到下一段 |
   | 电视、颗粒等纹理质感 | 资料、回忆或情绪段落的视觉气氛；参考剪Bingo子7.4秒、十一访谈拉片 | 查明当前可用效果的真实名称、资源身份、参数与作用层，形成可复用的调用示例 | 纹理作用于指定画面，文字和产品必要细节仍可辨认；资源可被实际草稿读取 |

   产物是上述效果的真实资源绑定、可复用调用示例，以及确有缺口的适配代码。代码位置以`video_effects.py`和现有资源入口为主，参数与兼容范围写回现有CandidatePlan合同。教程名称与本地资源身份逐项核对，当前缺失的资源继续标记为待落实。

   **3.2 新增动态局部与分层能力。**

   | 要新增的能力 | 当前边界及实现位置 | 应达到的画面结果 |
   | --- | --- | --- |
   | 蒙版位置、大小随时间变化 | 当前`video_mask.py`接受静态圆形/矩形；在对应共享模块补经8.8结构验证的动态参数和操作 | 窗口可从整体收缩到局部，并按指定时间点移动；保留需要的主体细节 |
   | 局部亮区跟随对象 | 组合底层压暗、上层清晰画面与动态蒙版；轨迹来自当前素材观察 | 亮区在过程中的关键时点也对齐嘴、手或实物，修正仅首尾对齐而途中偏离的问题 |

   | 多层对象同步运动 | 现有预设组变换主要处理预设稳定期；扩展共享变换或操作组合，统一媒体、前景与文字的关键时间点 | 整组进入、移动或退出时，各层相对位置与速度一致，避免人物抠像滞后于背景 |

   **3.3 落实可复用的复合效果组合。**

   在3.1、3.2与现有素材、字幕、关键帧能力上完成以下组合示例。每个示例明确层级、来源、进入过程、稳定观看期、退出和声音时间关系，并展开为同一CandidatePlan中的既有或新增共享操作。

   | 复合效果 | 组成与表达结果 |
   | --- | --- |
   | 背景定格模糊＋清晰人物＋人物后方文字 | 背景、前景与文字分别承担环境、讲述者和重点信息；需要时整组同步移动，保持前后关系 |
   | 底层压暗＋局部清晰窗口＋准确标注 | 先引导视线到具体部位，再让标注解释所见细节，随后恢复完整画面 |

   **3.4 按逐项依赖执行，并在原模块内补局部合成。**

   3.1—3.3用于组织说明，具体实施由清单中的变体及依赖决定。清单已逐项列出先做什么、必需输入、当前基础、共享模块、执行路径及可核对结果；其JSON中的`execution_alignment`和`execution`只供开发对照，不是新的CandidatePlan运行字段。新增参数、操作和兼容边界随实际代码一起写入现有合同，保持`visual_planning_version=2`；不能先在生产计划使用尚不存在的接口。

   | 执行环节 | 具体产出与边界 |
   | --- | --- |
   | 逐项确认变体和依赖 | 28项全部在范围内；其中“9种重点处理”“10款循环”按各变体落实，资源名未核对就保留待核对。12个共享工作单元只是代码依赖分组，不代表新建12个模块或限制效果数量 |
   | 按依赖贯通代表组合 | 可先做并列保留、普通回溯、透明前景、跟随聚焦；独立的资源查证、源观察及共享实现可同时推进。实例数量由能力差异决定，几个实例通过不能推定其他项目仅需改参数 |
   | 逐项补齐共享实现与组合 | 每项依据真实资源和输入完成可复用调用、同一CandidatePlan装配及相关验证。一个共用实现的相同验证可复用；不同变体的资源、对象、时序和边界仍须检查 |
   | 交给原整片流程 | 继续第4项的统一装配及必要程序检查、获准TEST写入和用户验收；局部技术样例与整片观感分别记录，反馈定向调整 |

   对原生不能可靠表达的局部倒放、抽帧、变形或透明前景，可在`material_library.py`及其现有入口补共享媒体处理，再经`material-register/use → add_broll`回到同一装配器。保留真实源文件、源区间、处理参数及输出映射；导出局部中间素材服务装配，成片导出权限仍按原规则。图像生成、真实源帧提取和局部媒体处理各按实际来源记录，不把后两者伪记为AI生成，也不绕过现有来源检查。字段与当前支持状态见[素材文档](../../../jianying-adapter/docs/MATERIAL_LIBRARY.md#局部合成与派生素材的开发边界)。

   首批已经修复`material_library.py`视频固定`alpha=False`的问题，按通道声明和全片实际解码值区分全透明、半透明及不透明，并接通保留已有alpha的加工。已有`render_portrait_composite.py`人物分割与合成基础继续复用；其统一回接、连续边缘及8.8实际叠加仍待对应实现/实例。透明度还涉及容器、编码、尺寸、帧率、PTS及色彩，不能由像素检查宣称原生兼容。普通不透明倒放无需等待该分支。具体原生能力先核对现有8.8结构依据，必要的新参考按实际GUI授权取得，不凭教程版本猜结构；独立工作继续推进。

   **人物、动态蒙版与完整组合的下一步落地。** 以下是后续实现路线，不是当前已经新增的命令。

   - 人物：复用[现有人像脚本](../../../jianying-adapter/scripts/render_portrait_composite.py)的模型会话、alpha推理、局部修复和预乘缩放，把可复用函数接入共享媒体模块，旧脚本收为调用该模块的薄入口。先核对本地权重和实际推理，再用同一真实源帧映射输出颜色与透明度，补连续透明视频及派生记录；不对前景、背景各自独立重采样。使用包含转头、手遮挡和发丝变化的短段，检查静帧和连续边缘；确有闪边时补运动对齐的时序处理，切镜与遮挡处重新判断，不能靠直接平均alpha制造拖影。
   - 动态蒙版：扩展现有`video_mask.py`，把窗口的位置/大小/形状/羽化与框内素材的取景分开控制。先从已有8.8参考取得真实动态字段；需要新增原生参考时按GUI授权取得。跟随点来自实际源观察或跟踪，并经源裁切、帧映射和画布转换。原生暂不可可靠表达的形状/轨迹可生成逐帧灰度遮罩，在共享媒体模块局部合成后回同一素材入口；灰度遮罩记录几何方法，不能冒充人物分割结果。
   - 完整组合：沿用`animation_recipes.py`已有配方，补参数到实际operations的展开；明确同一段的图层、共享锚点、进入/观察/退出时点和声音绑定。已有预设组运动先复用，需要跨人物/文字/背景时才扩展对应共享操作。多来源合成要保留所有实际输入及各自时间/许可，现有单父级派生合同也须随实现扩展，不能只登记成片来源而漏掉背景、文字或音效。

   先串起透明人物与后方文字/出框、跟随聚焦、多项末帧保留、完整回溯声画四种实例。它们用于验证不同依赖，28项67个变体仍分别落实。透明人物优先在8.8作为独立前景层，与文字/背景保持可编辑；若实际兼容不成立，可将确实需要合成的局部段落冻结成普通视频回接，修改其内部层级需重渲，该取舍不能藏在“原生可编辑”声明里。技术检查后按已授权范围交独立TEST，由用户判断实际声画；这轮路线核对未运行抠像或写入草稿。

   执行与回读同时区分三种交付：原片已经展示动作或细节时，核对所绑定源区间；新增原生运动或取景时，核对指定对象、关键位置及实际参数；定格或前置合成时，核对派生文件与源到输出关系。`scale=1`不是缺陷证据，微小非零变化也不是达成表达的证据。现有`graphic_motion`已拒绝无变化，新增检查应补对象与声明的一致性，继续复用当前报告，不新增审美打分或并行IR。

   **完成标准。** 必要设计所依赖的能力须在作品交付前补齐，或采用能够完成同一表达的可靠实现。清单按变体保留实际实现状态、技术证据、8.8兼容证据和用户观感；没有的部分保持待办，不借代表样例、JSON字段或文档齐全宣称完成。

   相关验证复用`test_video_effects.py`、`test_video_mask.py`、`test_material_library.py`、受影响的motion、`test_final_layout.py`及`test_visual_planning.py`。新增行为检查：资源身份和参数正确、指定层和时段正确、途中蒙版对齐、多层运动同步、标注位置准确、辅助媒体静音与声音时序正确。现有行为仅在受影响时补跑。

   同步补充`final_layout.py`和实际执行回读能够覆盖的新增几何与绑定；未建模的原生范围如实列明。自动检查证明装配事实，实际画面由8.8兼容样例及当前草稿的原生/用户结果分别记录。本轮完成情况按清单全部28项逐项核对：能力真实可调用、组合可装配、相关验证具备证据；尚未实现或验证的项保留明确状态。本计划的效果清单不表示这些能力现已实现。

4. **在同一装配与验收流程中验证整片收益。**

   按现行5.8把已有设计交CandidatePlan/CandidateAssembler，保留装配与Writer的必要程序检查，复用当前有效报告；具体报错当场修复，实际观感交用户播放审核。不新增独立Agent截图、切片、审美分数或逐段放行门禁；后续反馈按影响范围修改。

   在届时授权范围内，经唯一Writer写入独立TEST，交用户打开、播放并判断整片。开发中可用局部片段验证能力，但首个完整作品仍按整片交付；不让用户逐一批准预设或效果。反馈落在原`project_state.json.internal_review`及当前草稿，按时段和问题定向调整。

   验收围绕实际观看结果：细节能否辨认，比较是否直观，动作是否连续，画面是否有主次，变化是否连贯，文字是否易读，声音是否适合内容。结构检查证明执行准确，用户反馈决定当前整片的实际观感是否接受。

**推荐执行顺序是：1确定画面表达；2与3按真实依赖落实素材、预设及特效能力；4统一装配和整片验收。** 第3项是明确的开发工作包，依赖其中能力的组合必须先完成对应实现。第一轮开发让细节、比较、空间层次、情绪和视觉连贯的做法在现有管线中落地，把教程理解落实到实际画面、时序和装配结果。
